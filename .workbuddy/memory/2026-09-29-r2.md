# 2026-09-29 · 第 2 轮 P0：SSE 事件全部丢失 → 平台稿全链路打通

## 结论先行
真实浏览器复现并修掉 **「文章提交后永远停在 brief 面板」** 的 P0。客户端拿本地 UUID 当过滤 token、服务端回自己的 UUID，过滤永远命中 → 所有 SSE 事件被静默丢，正文写不进 localStorage。Codex + Claude 并行评审又找出第二轮 SSE 健壮性问题与两处残留 window.prompt，全部修掉。

## 复现路径
1. `pnpm dev` 起服务
2. 打开首页 → 输入素材 → 提交
3. 等 90 秒：UI 永远停在「AI 正在生成母稿」但 progress label 不前进；点 原稿/发布包 标签都是 disabled；`localStorage` 里 `content` 为空
4. curl 单独打 `/api/generate/stream`：服务端 21 秒返回完整正文 + verify + done

## 根因（app/article/[id]/page.tsx）
```ts
if (event.requestId && event.requestId !== localRequestId) return;
```
- 客户端在 `onGenerate` 入口用 `crypto.randomUUID()` 起了一个 `localRequestId`
- 服务端在 `app/api/generate/stream/route.ts:37` 独立生成 `requestId`，每个事件都附上
- 两端 UUID 互不可见 → 每一类事件（stage / delta / verify / done）都被丢
- AbortController + 循环退出本就能挡住串流旧请求，这个过滤是死代码

## 修复链
1. **删掉** requestId 过滤（`app/article/[id]/page.tsx`）
2. **补全** 'done' 分支 setGenerationProgress 的 requestId（之前漏，`...previous` 救场但显式更稳）
3. **新增 4 个回归测试**（`tests/streaming-request-id.test.ts`）：
   - requestId 不一致也接受
   - `: ping` 心跳不炸
   - 空 `data:` 行被吞
   - 坏 JSON 数据被吞而后续事件仍到达
4. **Codex 第二轮**：删 [DBG] 日志；stage / done reducer 加 verdict 保留；JSON.parse try/catch
5. **Claude 第二轮**：delta branch 在 previous 为 null 时给一份初始 state，避免静默丢
6. **删残留 window.prompt**：`components/Editor.tsx:176` 图注 prompt 改成无 prompt 直接插入（用户点击图片后用工具栏补 caption）
7. **删残留 window.confirm**：`app/marketplace/page.tsx:119` 自定义 Agent 删除换成 3 秒两段确认（沿用 AppShell 同一套模式）
