# 二期实施方案（把关后）

## 0. 裁决结果

**两个待裁决问题**

1. **backlog #6 两级 tab 合并：推迟。** 同意你的判断。两边数据源不同，合并就得重构组件，而公众号子 tab 现在能用。这一轮做完 verify 异步和一键应用后，文章页标题行会少一类信息过期的问题。等 #1 流式写入编辑器重新设计落盘语义时，再统一考虑文章页的信息架构，比现在单独动 tab 划算。
2. **PlatformTabs「生成其余 N 个平台」：改成 ghost，复制保持 primary。** 理由有两条：
   - 一期定下的规则是"复制是唯一的实心按钮"，二期不再留例外。
   - `remainingCount === 0` 时这个按钮已经是 ghost（文案是"全部重新生成"）。统一成 ghost 之后，按钮样式不再分两种情况，只剩文案按 `remainingCount` 切换，代码比现在更少。

**对你拟的包的调整（我核对了代码，有 4 处需要改）**

- **P1 原方案达不到效果，必须同时改客户端。** `page.tsx` 的读循环要读到服务端关流才退出，退出后才走 `if (!completed)`、等 500ms、`selectWorkspaceStep('editor')`，`finally` 里才 `setGenerating(false)`。所以只在服务端把 `done` 提前，用户照样要等核查结束才能进编辑器。核查最长可以拖到 90 秒（`cross-validate.ts:104` 的 CLI 超时），这正是 P1 要解决的痛点。另外异步之后会出现两个竞态：迟到的 verify 盖到对话改稿后的正文上，或者盖到下一次生成上。必须加防护。
- **P2 不能走 `onCreativeCommand`。** `@主编` 被路由到 chief-editor 后，剥掉 @ 的指令还会继续经过关键词分支：
  - 建议里只要出现"知乎、小红书、平台稿"，`inferPlatformsFromInstruction` 就会跑去批量生成平台稿；
  - 出现"模板、版式"会切换模板；
  - 同时含"正文/编辑"和"查看/打开"会只打开编辑器。

  核查建议里出现这些词的概率很高。所以要把 refine 那一段抽出来直接调用。
- **P3 和 P4 合并成一个包。** `Editor.tsx` 里还有一个 `text-[11px]`（第 184 行），两个包会改到同一个文件。P4 的清单还漏了两个文件：`AgentStudio.tsx`（两处 `[12.5px]`）和 `AiSetupGuide.tsx`（`[12.5px]`、`[12px]`）。文章页标题输入框的 `text-[22px]` 在 `page.tsx` 里，划给 WP1，避免同一文件两人改。
- **P1、P2、P7 合并成 WP1。** 三者都改 `page.tsx`，交给同一个人顺序完成。

**发现已经做完、不必再列的事项**：验收报告"建议修"的 5 条在 dd4df87 里都已落地（浮层点外部关闭、摘要文字 `hidden sm:inline`、改稿后 `setVerdict(null)`、最近内容 `articles.length > 0`、保存长图的 `title`）。

**没有砍掉的包。** P8 增加一个改动：把新词同步写进生成 prompt（`src/lib/ai.ts:267`）。只在生成后检测、不在生成前预防，不算 AI native。

**注意**：`.claude/worktrees/` 下有 9 份旧副本会污染 grep 结果（比如 `?write=1` 在那里还有入口），所有 grep 验收都要排除这个目录。

## 1. 最终工作包

### WP1：verify 异步 + 核查建议一键应用 + 死分支清理（主线程或单人顺序做）

**文件**：`app/api/generate/stream/route.ts`、`app/article/[id]/page.tsx`

**改动**

1. **服务端，`route.ts` 第 127–145 行**
   - 顺序改为 `send(done)` → `try { await crossValidateDraft(...); if (verdict) send(verify) } catch {}` → `clearInterval(heartbeat)` → `if (!cancelled) controller.close()`。
   - heartbeat 要等核查结束后再清，因为核查最长 90 秒，期间要靠心跳保持连接。
   - 注释改成"done 先发，核查异步跟进，失败或超时不影响已交付正文"。
2. **客户端读循环，`onGenerate`**
   - 把现有的 `while (true)` 解析循环抽成 `onGenerate` 里的局部函数 `pump(stopWhen: () => boolean)`。
   - 主流程调用 `await pump(() => completed)`。读到 `done` 后立刻退出循环，后续的进编辑器、`runPlatformBatch`、`finally` 和原来一样执行。
   - 然后 `void pump(() => false).catch(() => {})` 在后台继续读，只消费 verify 事件。
   - 新增 `verdictRunRef = useRef(0)`：`onGenerate` 开始时 `+1` 并记下 `runId`；refine 成功调用 `setVerdict(null)` 的地方也 `+1`。
   - verify 分支改成 `if (runId === verdictRunRef.current) setVerdict(event.verdict)`。
   - `setGenerationProgress` 里写 verdict 的那段可以留着（previous 为 null 时本来就是空操作），也可以删掉。
   - 更新第 63 行的注释。
3. **抽出 refine**
   - 把 `onCreativeCommand` 里从 `if (aiReady === false) throw ...连接 AI 后才能继续改稿` 到改稿收尾消息的这一段，原样抽成 `async function runRefine(instruction: string, agentId: CreatorAgentId)`。
   - `onCreativeCommand` 改为调用它，行为不变。
4. **一键应用**
   - 在 verdict 浮层底部，`issues` 或 `suggestions` 非空时，显示 ghost 按钮「让 AI 按建议修改」。
   - 点击后依次：`details.open = false`，`addConversationMessage('user', '按核查建议修改')`，`setCommandBusy(true)`，`await runRefine(拼接后的指令, 'chief-editor')`，`finally setCommandBusy(false)`。错误处理复用 `onCreativeCommand` 的 `showError` 路径。
   - 指令格式：`按以下核查意见修改全文，只改涉及的段落，保留其余内容：\n问题：\n- …\n建议：\n- …`。
   - `commandBusy || generating || batchProgress` 任一为真时禁用按钮。
   - 成功后 `runRefine` 内部已经会 `setVerdict(null)`，浮层随之消失。不要自动重新核查。
5. **死分支清理**：`initialWorkspaceStep` 的 `return` 改成 `'brief'`；`selectWorkspaceStep` 删掉 `url.searchParams.delete('write')`。
6. **字号**：标题 input 的 `text-[22px]` 改成 `text-2xl`。

**不做**：verdict 持久化、核查中的 loading 指示、应用建议后自动重新核查、done 之后的取消入口（后台读流不响应停止按钮，这是可以接受的）。

**验收**
- 用 mock 让核查延迟 10 秒：done 后 1 秒内进入编辑器，约 10 秒后标题行出现核查摘要。
- 核查进行中触发对话改稿，迟到的 verdict 不出现。
- 核查进行中重新生成，旧 verdict 不出现。
- 建议里含"小红书 / 模板"时，一键应用走的是 refine，不会触发平台批量生成或切换模板。
- `grep -n "'write'" 'app/article/[id]/page.tsx'` 结果为 0。
- `tsc` 和 `pnpm test` 全绿。
