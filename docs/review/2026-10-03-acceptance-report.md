## 三、发现的问题

**必须修：** 无。

**建议修：**
1. **核查浮层在移动端可能超出屏幕**（`app/article/[id]/page.tsx:883`）。浮层是 `absolute right-0 w-72`，在窄屏上，摘要按钮跟在标题输入框后面，离左边不到 288px，浮层左侧就会伸出屏幕。另外"已通过 AI 核查"的文字在移动端也会挤压标题输入框。建议摘要文字改成 `hidden sm:inline`（和旁边"排版预览"的做法一样），浮层在移动端改成 `left-0` 或加 `max-w-[calc(100vw-2rem)]`。
2. **核查浮层点外面不会关**（同上）。原生 `<details>` 没有点外部关闭的行为，展开后会一直盖在编辑器正文上，直到再点一次摘要。
3. **核查结论可能过期**。对话修改（`commandBusy` 那条路径，`:629`）改动正文后，标题行仍显示上一次生成的"已通过 AI 核查"。建议在对话修改成功时调用 `setVerdict(null)`，或者把文案改成"生成时已通过核查"。
4. **最近内容空状态只剩标题**（`app/page.tsx:62-65`）。没有文章时，移动端仍会显示"最近内容 / 自动保存在当前浏览器"，下面是空的。建议整个 section 用 `articles.length > 0` 包起来。
5. **保存长图按钮只剩图标**（`components/PreviewPane.tsx:89`）。只有 `aria-label`，鼠标用户悬停时看不到提示。建议加 `title="保存长图"`。

**可忽略：**
- `PlatformTabs.tsx:143`：还有剩余平台没生成时，底栏"生成其余"仍是 primary，和"复制是唯一实心按钮"冲突。这是方案自己前后矛盾（WP3 第 2 条要求它保持 primary），不算施工偏差。
- 流面板每次内容更新都会强制滚到底（`GenerationProgress.tsx:42`），用户往上翻的时候会被拽回来。
- 流面板显示的是 markdown 原文，`#` 和 `**` 符号会露出来，不过段落已经能读。
- QuickComposer 的 Agent 菜单有 10 项，高约 500px，会被外层 `overflow-hidden` 截掉（`:178`）。这是原来就有的问题：高级行就在输入框正下方，菜单向上弹出的可用空间和改动前一样，不是本轮引入的。
- Markdown 平台（知乎、CSDN 等）原来的渲染预览没了，改成直接显示原文文本框。这是方案有意为之。
